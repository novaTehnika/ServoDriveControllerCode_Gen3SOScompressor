## Notes on PRG_Main.st
For EOT homing, I think we need to limit the torque for the fast jog, just in case the approach distance we set over-shoots the EOT.
As I understand it, the use of fbSetPosition within ST_HOME_EOT_SETREF will overwrite the position set during ST_HOME_LIM_SETREF. Instead, we should store an offset distance so that we retain an accurate reference to the homing switch. Stepping back, I believe the sequence should be as follows: 1) Home-to-limit routine is executed (whether programmatically required or not), the positive side of the limit switch is found, and the Absolute encoder position is set to zero at that location, 2) requirement to home to limit is set to satisfied and requirement to Home to EOT is set to NOT satisfied, 3) home-to-EOT routine is executed using configured landmark position estimates, the EOT is determined, and the offset from the configured estimates for EOT and cylinder exit limit (initialized to zero) are set to account for the determined EOT position. 4) position commands from the master are mapped accounting for this offset. So, counter to earlier declarations (which you may or may not be aware of) we will have two coordinate systems: 1) a coordinate system based on the absolute encoder position zeroed to the limit switch being used for homing and 2) a coordinate system that is offset based on the EOT position determined in the home-to-EOT routine.
ST_FAULT should NOT engage the brake!
The timeout in ST_FAULT should NOT lead to ST_IDLE. ST_IDLE is not set up to handle the fault handshake and we should avoid complicating the logic of that state with so much logic to handle. Instead, we need a dedicated fault-idle state and associated transition states.
